## US3 — Analyse statique du malware (version simple)

But : comprendre ce que fait le malware **sans l'exécuter**, juste en lisant
les fichiers. L'archive `Malware.zip` contient un dossier `VIRUS/` avec
**2 programmes** + le moteur Qt (7 DLL livrées avec).

| Fichier | Rôle | Preuve |
|---|---|---|
| `Res.exe` (25 Ko, console) | S'installe, se met en démarrage auto, **enregistre les touches du clavier** | screens 2, 3, 4 |
| `Env.exe` (53 Ko, fenêtre) | **Envoie le fichier de frappes par e-mail** (SMTP + TLS) | screens 5, 6 |
| 7 DLL Qt5 / MinGW | Bibliothèques normales, livrées pour que ça marche sur n'importe quel PC | screen 1 |

Résultat : c'est un **keylogger avec exfiltration par e-mail**. Cela colle
exactement au verdict VirusTotal de l'US2 (`Win32/Spy.KeyLogger`).

## Comment j'ai fait — les étapes

Outils : `unzip`, `file`, `strings` (chaînes de texte), `pefile` (lecture
d'en-tête Windows/PE), `capstone` (désassembleur). Tout hors-ligne, sur un
poste isolé. Chaque étape a une capture d'écran dans `US3/screens/`.

**Étape 1 — Extraire et identifier** → `screens/01-extraction-identification.png`
```
unzip -l Malware.zip          # voir le contenu
file Env.exe Res.exe          # type de fichier : PE32 Windows i386
sha256sum Env.exe Res.exe     # empreintes (IOC)
```
On voit : 2 exécutables Windows 32 bits + les DLL de Qt 5.9 (compilé MinGW).

**Étape 2 — Lire les chaînes de `Res.exe`** → `screens/02-res-strings.png`
```
strings -a Res.exe
```
Chaînes parlantes : `c:\WindSyst\log.txt`, `mkdir c:\WindSyst`,
`XCOPY Res.exe c:\WindSyst /S`, `...\CurrentVersion\Run`, `GetAsyncKeyState`,
et une signature d'auteur `code par le magniquime Hafnium !`.

**Étape 3 — Lister les imports de `Res.exe`** (fonctions qu'il appelle)
→ `screens/03-res-imports.png`
```
python -c "import pefile; pe=pefile.PE('Res.exe'); ...afficher les imports..."
```
On trouve : `GetAsyncKeyState` / `GetKeyState` (clavier), `ShowWindow` (cacher
la console), `system` (lancer des commandes), `QSettings::setValue` (écrire
dans le registre), `std::thread` (tâche de fond).

**Étape 4 — Désassembler `Res.exe`** pour confirmer la persistance
→ `screens/04-res-disasm-persistance.png`
```
python -c "
import pefile, capstone
pe = pefile.PE('Res.exe'); img = pe.get_memory_mapped_image()
base = pe.OPTIONAL_HEADER.ImageBase
md = capstone.Cs(capstone.CS_ARCH_X86, capstone.CS_MODE_32)
for i in md.disasm(img[0x401aa0-base:0x401aa0-base+220], 0x401aa0):
    print(hex(i.address), i.mnemonic, i.op_str)
"
```
(commande unique en ligne, pas de script externe : `pefile` lit le PE, `capstone` désassemble)
Dans la fonction `0x401aa0` on lit, dans l'ordre : cacher la console →
`system("mkdir c:\WindSyst")` → série de `system("XCOPY ... c:\WindSyst")` →
`QSettings(...Run...).setValue("Res","C:\WindSyst\Res.exe")` et
`setValue("Env","C:\WindSyst\Env.exe")`. => persistance prouvée.

**Étape 5 — Chaînes + imports réseau de `Env.exe`**
→ `screens/05-env-strings-imports.png`
```
strings -a Env.exe
python -c "import pefile; ... imports ..."
```
Chaînes : `c:\WindSyst\log.txt`, `smtp.laposte.net`,
`aaaaaaaaaaaa@laposte.net`, mot de passe `z98tmFrance`,
`aaaaaaaaaaaa@gmail.com`, commandes `AUTH LOGIN`, `MAIL FROM:<`, `DATA`...
Import clé : `QSslSocket::connectToHostEncrypted` (SMTP chiffré).

**Étape 6 — Désassembler `Env.exe`** (fonction d'envoi `0x4016b0`)
→ `screens/06-env-disasm-exfiltration.png`
```
python -c "
import pefile, capstone
pe = pefile.PE('Env.exe'); img = pe.get_memory_mapped_image()
base = pe.OPTIONAL_HEADER.ImageBase
md = capstone.Cs(capstone.CS_ARCH_X86, capstone.CS_MODE_32)
for i in md.disasm(img[0x4016b0-base:0x4016b0-base+400], 0x4016b0):
    print(hex(i.address), i.mnemonic, i.op_str)
"
```
La fonction ouvre `c:\WindSyst\log.txt`, le lit, crée un objet `Smtp` avec
serveur / login / mot de passe **écrits en dur**, port `465`, puis appelle
`sendMail(from=laposte, to=aaaaaaaaaaaa@gmail.com, sujet="aaaaa !", corps=log)`.
Cette fonction est appelée depuis le constructeur de la fenêtre → **envoi
automatique dès le lancement, sans clic**.

## Ce que fait le malware (scénario)

1. La victime lance `Res.exe` (depuis la clé USB — cf. US9/US10).
2. `Res.exe` cache sa fenêtre, crée `C:\WindSyst\` et s'y recopie avec
   `Env.exe` et les DLL Qt.
3. Il ajoute 2 entrées dans `HKCU\...\CurrentVersion\Run` (`Res` et `Env`) :
   les 2 programmes se relancent à **chaque ouverture de session**.
4. Un thread lit le clavier en boucle (`GetAsyncKeyState`, toutes les 10 ms)
   et écrit chaque touche dans `C:\WindSyst\log.txt`.
5. `Env.exe` lit ce fichier et l'**envoie par e-mail** (SMTP + TLS via
   `smtp.laposte.net:465`) vers `aaaaaaaaaaaa@gmail.com`, la boîte de l'attaquant.

## Fonctions principales identifiées

| Programme | Adresse | Fonction | Ce qu'elle fait |
|---|---|---|---|
| Res.exe | `0x4035aa` | `main` | lance le thread keylogger + l'installation |
| Res.exe | `0x401640` | keylogger | boucle clavier → écrit `log.txt` |
| Res.exe | `0x401aa0` | installation | cache console, `XCOPY` vers `C:\WindSyst`, clés Run |
| Env.exe | `0x401e30` | constructeur fenêtre | appelle l'exfiltration automatiquement |
| Env.exe | `0x4016b0` | exfiltration | lit `log.txt`, prépare l'e-mail |
| Env.exe | `0x402070` | `Smtp::sendMail` | dialogue SMTP (`EHLO`,`AUTH LOGIN`,`DATA`,`QUIT`) |

Note : binaires **non packés** (entropie ~5,9), pas de chiffrement, pas
d'anti-debug : lecture directe possible.

## Indicateurs de compromission (IOC)

**Fichiers / dossiers**
- `C:\WindSyst\` (+ `log.txt`, `Res.exe`, `Env.exe`, `platforms\`, DLL Qt)

**Registre (démarrage automatique)**
- `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Res` = `C:\WindSyst\Res.exe`
- `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Env` = `C:\WindSyst\Env.exe`

**Réseau / e-mail**
- Serveur : `smtp.laposte.net:465` (TLS)
- Émetteur : `aaaaaaaaaaaa@laposte.net` / mot de passe `z98tmFrance`
- Destinataire (attaquant) : `aaaaaaaaaaaa@gmail.com`
- Sujet : `aaaaa !`

**Hachages SHA-256**
- `Res.exe` : `49f091ade48890bfa22d2b455494be95e52392c478b67e10626222b6aee37e1e`
- `Env.exe` : `e09ec2098363a129de143fdaf73ad6e2e61266fba3f638a25214af3a8bc8f2f2`

**Signatures texte (pour une règle YARA)**
- `code par le magniquime Hafnium !`
- `WindSyst`, `z98tmFrance`, `aaaaaaaaaaaa@gmail.com`

**Comportements**
- fenêtre console masquée (`ShowWindow`)
- processus enfants `cmd.exe /c mkdir` et `xcopy`
- capture clavier permanente (`GetAsyncKeyState`)
